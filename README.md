# YomShishi 3x3 PWA

Closed-group app for managing Friday 3v3 basketball games with manual game creation, automatic waitlist logic, and push reminders.

## Architecture

- Frontend: React + Vite + TypeScript, mobile-first RTL Hebrew UI, installable PWA.
- Backend: Node.js + Express, SQLite-compatible storage via `sql.js` persisted to disk (`backend/data/yomshishi.sqlite`).
- Authentication: Google Sign-In only (no password / no email verification flow in app).
- Session persistence: user id stored in localStorage for future actions.
- Group policy: only pre-approved emails can register (`APPROVED_EMAILS`).
- Admin policy: any approved participant can create the next game, but only emails in `ADMIN_EMAILS` can edit or delete an existing game.

## Game Rules Implemented

- Games can be created manually by an admin or generated by a weekly schedule. When enabled, registration opens automatically every Monday at the configured Israel time, for a game later that week on the configured weekday and time. Enabling the schedule after Monday's opening time starts it the following Monday.
- The weekly schedule is disabled by default and is configured from the admin screen. The server checks it every minute; a per-week record prevents duplicate games, including after a generated game is deleted.
- The player who creates a game is not auto-registered and must join like everyone else.
- Registration remains open after the lottery; the game does not lock at the cutoff.
- The lottery runs automatically at 21:00 Israel time on the day before the game.
- OPEN: 0-5 players
- CONFIRMED: every registered player currently has a playing role
- Before the lottery, 10-11 players all remain in the playing role.
- Up to 9 players: everyone plays, with no lottery.
- 10-11 players after the lottery: one or two players wait, respectively.
- WAITING: one or more players are assigned to the late-arrival list.
- Exactly 12 players: everyone plays and any waiting status is cleared.
- After the lottery, new registrations are automatically assigned to the waiting list; players above position 12 wait automatically.
- Waiting players arrive about one hour after the game starts.
- Player profiles support an optional public photo, email, phone, and free-form details. Photos are resized in the browser and stored in the local SQLite database.
- Active players who have not registered for a game for two consecutive months are automatically deactivated by the server.
- An injury status exempts a player from inactivity cleanup until the selected injury end date. The end date can be extended from the injury screen.
- Active injured players and their injury end dates are displayed alongside each game roster.

## Local Run (No Admin Required)

1. Backend:
   - Copy `backend/.env.example` to `backend/.env` and set values.
   - Set `GOOGLE_CLIENT_ID` to the exact OAuth Web Client ID used by the frontend domain.
   - Run `npm install` in backend.
   - Run `npm run dev` in backend.
2. Frontend:
   - Copy `frontend/.env.example` to `frontend/.env`.
   - Keep `VITE_API_BASE_URL` empty when frontend is served from the same backend host.
   - Run `npm install` in frontend.
   - Run `npm run dev` in frontend.
   - The Vite development server proxies `/api` to the local backend at `http://localhost:8787`.

## Court Run Arcade

- The arcade tab stars Itai Shlomi (#7), independently of the signed-in account.
- Uses the official [Pyxel 2.9.9 Web runtime](https://github.com/kitao/pyxel) in an isolated iframe. Python game code and the host page live in `frontend/public/games/` and must be deployed alongside `dist/index.html`.
- Designed for phones held sideways: landscape expands to the viewport; portrait pauses the game and displays a rotation prompt. Native fullscreen and orientation locking depend on browser support; the viewport fallback remains available.
- Dedicated multi-touch buttons provide movement, double jump, dash, fire shots, pause and restart. The course includes safe checkpoints, cones, rivals, green/orange/red power-ups, score combos and a dunk finish. Green grants an extra life; orange and red grant timed growth and fire respectively.
- Pyxel/Pyodide and Lucide icons load from pinned CDN URLs, so initial loading requires an internet connection. Sound starts after the player's first tap. Pyxel and Lucide are MIT-licensed upstream projects; game artwork is drawn with Pyxel primitives.
- From the repository root, run `python -B -m unittest discover -s frontend/tests -p test_court_run.py -v` for focused mechanics tests (drawing/audio mocked). Also run `npm --prefix frontend run build` and verify real Pyxel rendering, multi-touch, rotation, fullscreen exit, and pause in a browser. Phone emulation does not replace a physical iOS/Android device check.

## Scheduled Lottery

- The backend checks upcoming games every minute.
- At 21:00 Israel time on the day before a game, it recalculates player roles and saves the roster snapshot.

## Game Timer Audio

- The web timer and local Android foreground/AOD timer use recordings from [elay96/basketball-sfx](https://github.com/elay96/basketball-sfx/tree/aa90345ab68c649bbc7fde29a40de41338f9d183), revision `aa90345ab68c649bbc7fde29a40de41338f9d183`. The project owner confirmed permission to use and distribute these recordings; upstream has no published license. Only the six timer recordings are used, not the unrelated SFX collection.
- Announcements play on a fresh start, at 5 minutes, 2 minutes, 1 minute, each of the final 10 seconds, and zero. Resume does not repeat the start announcement. There is no 30-second recording, so the former synthesized 30-second announcement is removed.
- In addition, seven random Hebrew commentary clips (`random-itai-three.mp3` with a crowd disappointment groan at the end, `random-elay-save.mp3`, `random-noam-three.mp3`, `random-moshon-score.mp3`, `random-salvador.mp3`, `random-fali.mp3`, and `random-neta.mp3`) are scheduled at random non-overlapping seconds during a running game, avoiding the 5-minute, 2-minute, 1-minute, and final countdown windows.
- Random commentary was regenerated on 2026-10-30 using ElevenLabs Eleven v4 and the Hebrew voice **Herzl Ben - Articulate, Clear** (stability 50%, similarity 75%, no voice effects). The owner approved Generation 2 of the Noam sample. These replace the old Windows speech synthesis recordings; official time announcements and countdown recordings are unchanged. Keep speech intact at its original speed, without silence-removal filters or aggressive amplification. The Itai clip appends a separately generated two-second crowd reaction after a short gap, never over the speech. Each complete random clip must remain under five seconds to fit the existing milestone safety margin.
- Audio is generated once and bundled locally; no ElevenLabs credentials, API calls, or credit usage are needed during games. When replacing recordings at the same URLs, bump the service-worker cache version and rebuild the Android APK so installed clients do not retain the old audio.
- The source countdown lasts about 8.25 seconds, not 10. It is split at silent gaps into ten individual number clips, without changing speech speed, so each number starts at its matching second. Extraction ranges (seconds, from ten to one): `0-0.720975`, `0.940771-1.581450`, `1.681180-2.355420`, `2.521160-3.172470`, `3.321130-4.004780`, `4.085690-4.854990`, `4.984380-5.567780`, `5.681160-6.434010`, `6.557010-7.309500`, `7.504780-8.250000`. Clips were encoded with FFmpeg `libmp3lame` at 128 kbps.
- Web assets are bundled under `frontend/public/audio/timer/`, resolved relative to Vite's base path, and precached by the service worker for offline use after installation. Playback unlocks on Start/Resume. Browser background throttling is platform-dependent; Android's native service uses the identical clips in `android/app/src/main/res/raw/` and continues with the screen off, without requiring Hebrew TTS.
- Pause/reset stops the current clip. A delayed tick plays only the latest crossed milestone rather than queuing obsolete announcements. A new game begins with the start recording even when its initial duration equals a milestone.
- Validate with `node --test frontend/tests/timer-audio.test.mjs`, `npm --prefix frontend run build`, and `android\gradlew.bat -p android :app:assembleDebug`. Installing an updated Android APK is required for native audio changes; a web deployment alone does not update the packaged recordings.
